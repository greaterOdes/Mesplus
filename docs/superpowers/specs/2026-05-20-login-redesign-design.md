# Mesplus 登录页与登录策略重构设计

## 背景

当前登录页与 `2026-04-30-mesplus-harmony-app-design.md` 中“配置化渠道登录、可扩展登录策略”的目标存在偏差：页面视觉偏普通表单，登录方式仍带有占位性质，MAG 首设备双因子认证和 IDASS WebView 回调认证流程没有完整表达。

本次设计目标是重构登录入口，使工业软件登录体验消费级化：参考 iOS、macOS 与 Apple Human Interface 风格，使用大留白、毛玻璃、高级灰、超细线、极简图标与克制微动效，同时保留 B 端工业系统需要的安全认证流程。

## 范围

本次需求覆盖：

- 登录页视觉重构为 Apple HIG 风格。
- 登录方式只保留 `MAG` 和 `IDASS`。
- 移除第三种普通账号密码直登方式。
- MAG 支持账号密码、设备 ID、首次设备双因子认证。
- IDASS 支持 WebView、JS 注入回调、MTOKEN 换取服务端会话。
- 登录框架保持策略化、配置化和可扩展，新增登录方式不改动既有登录方式代码。

本次需求不覆盖：

- 真实后端接口字段的最终确认。
- 真实短信、邮箱验证码服务的生产联调。
- 首页、通讯录、工作日志、个人中心的业务页面重构。

## 视觉设计

登录页采用“纯 HIG 毛玻璃登录卡”方向。

视觉原则：

- 背景使用浅灰到银白渐变，叠加柔和光斑，不使用强烈工业大屏风。
- 主登录卡使用半透明白色、细边框、轻阴影和圆角，模拟毛玻璃层次。
- 品牌区保留 `Mesplus`，副标题表达精密制造、安全访问、工业协同等定位。
- 交互控件使用高级灰、系统蓝或深灰黑作为主色，不使用传统 ERP 高饱和配色。
- 图标保持极简线性风格，按钮和输入框使用细线、轻背景、低噪声视觉。
- 微动效只用于渠道切换、二次认证区域展开、按钮按压反馈，避免复杂动画。

## 登录入口结构

登录页由 `LoginContent` 作为页面容器，`LoginPanel` 作为登录卡片主体。

登录卡片内部结构：

- 品牌与说明区。
- 登录渠道切换区：`MAG` / `IDASS`。
- 当前登录渠道对应的表单或说明。
- 登录状态提示：加载中、等待验证码、认证失败、认证成功。
- 底部辅助说明：设备安全、企业身份认证、自动登录提示。

渠道切换只改变当前登录策略和界面状态，不直接耦合具体认证接口。

## MAG 登录流程

MAG 是账号密码登录渠道，账号和密码与其他渠道隔离。

流程：

1. 用户选择 `MAG`。
2. 用户输入账号和密码。
3. App 登录请求传入账号、密码和设备 ID。
4. 服务端判断是否首次在当前设备登录。
5. 如果不是首次设备登录，服务端返回可归一化的用户信息和会话信息，App 创建 Session 并进入首页。
6. 如果是首次设备登录，服务端返回需要双因子认证状态，以及脱敏手机号和脱敏邮箱。
7. 登录卡片内展开二次认证区域，用户选择短信验证码或邮箱验证码。
8. 用户请求发送验证码并输入验证码。
9. 验证通过后，服务端返回可归一化的用户信息和会话信息，App 创建 Session 并进入首页。

二次认证 UI 不跳转页面，不弹出额外 Sheet，而是在同一毛玻璃卡片内展开，保持 iOS 表单式连续体验。

## IDASS 登录流程

IDASS 是内嵌 WebView 登录渠道。

流程：

1. 用户选择 `IDASS`。
2. App 打开内嵌 WebView 登录页。
3. App 注入约定函数 `window.Loader.intoApp`。
4. IDASS Web 页面认证成功后调用：

```js
window.Loader.intoApp(JSON.stringify({
  mtoken: "xxx",
  user: {}
}))
```

5. App 解析 JSON 字符串，提取 `mtoken` 和初始用户信息。
6. App 再次调用服务端认证接口并传入 `mtoken`。
7. 服务端认证成功后返回可归一化用户信息和会话信息。
8. App 创建 Session 并进入首页。

IDASS 只在 MTOKEN 二次服务端认证成功后才算登录成功，不能仅凭 Web 回调直接进入首页。

## 登录策略架构

继续使用 `LoginStrategyRegistry` 思路，但将登录策略升级为更清晰的状态化流程。

核心角色：

- `LoginStrategy`：定义登录方式的能力边界。
- `MagLoginStrategy`：处理 MAG 账号密码、设备 ID、二次认证。
- `IdassLoginStrategy`：处理 IDASS WebView 回调 payload 和 MTOKEN 服务端认证。
- `AuthService`：只调度策略、归一化登录结果、保存 Session，不写具体登录方式细节。
- `LoginPanel`：只根据当前登录状态渲染 UI，不拼接接口 URL。
- `channels.json`：配置登录方式、服务路径、JS 回调名称、双因子认证路径等。

后续新增登录方式时，只新增策略类、配置项和注册代码，不修改 MAG 和 IDASS 策略内部逻辑。

## 配置调整

`channels.json` 中 `loginMethods` 只保留两类：

- `MAG`
- `IDASS`

MAG 配置需要表达：

- 登录服务。
- 登录路径。
- 设备 ID 字段名或由策略统一注入。
- 短信验证码发送路径。
- 邮箱验证码发送路径。
- 双因子验证码校验路径。
- 自动登录路径。

IDASS 配置需要表达：

- Web 登录服务。
- Web 登录路径。
- JS 回调函数名：`window.Loader.intoApp`。
- MTOKEN 服务端认证路径。
- 自动续期路径。

## 错误处理

- 账号或密码为空时，MAG 不发起登录请求，卡片内提示。
- 首设备认证需要手机号或邮箱，但服务端未返回任何可用认证方式时，提示“当前账号缺少可用双因子认证方式”。
- 验证码发送失败或校验失败时，保留当前二次认证区域，并显示错误提示。
- IDASS 回调 payload 为空、不是 JSON 字符串、缺少 `mtoken` 时，不进入首页，显示认证失败提示。
- MTOKEN 服务端认证失败时，留在 IDASS 登录页或返回登录卡片，并提示重新认证。

## 测试与验证

实现时需要覆盖：

- MAG 非首设备登录成功路径。
- MAG 首设备登录返回二次认证状态。
- MAG 短信验证码和邮箱验证码选择状态。
- MAG 验证码通过后创建 Session。
- IDASS `window.Loader.intoApp` JSON 字符串解析。
- IDASS 缺少 `mtoken` 时拒绝登录。
- IDASS MTOKEN 服务端认证成功后创建 Session。
- `LoginStrategyRegistry` 新增策略时不影响已有策略。
- 编译验证、模拟器安装和启动验证。

## 验收标准

- 登录页视觉明显区别于传统 ERP 表单，符合 Apple HIG 风格方向。
- 页面只展示 `MAG` 和 `IDASS` 两个登录渠道。
- MAG 登录支持设备 ID 和同一卡片内二次认证展开。
- IDASS 使用 `window.Loader.intoApp(JSON.stringify({ mtoken: "xxx", user: {} }))` 作为 WebView 回调约定。
- IDASS 必须通过 MTOKEN 二次服务端认证后才进入首页。
- 普通账号密码直登入口不再展示。
- 新增登录方式不需要修改 MAG 或 IDASS 既有策略代码。
- 通过 HarmonyOS 编译验证。
- 如果模拟器已启动，安装构建后的 HAP 并启动主 Ability 验证。
